# 식수센스(SNP) — 3~4분 최종발표 시연 시나리오

작성일2026-10-19. 새 sprint-final 브랜치의 현재 구현을 대상으로 한다. 화면 증거는 [07 검증·스크린샷](07_demo_and_screenshots.md)에 있다. 최신 Optuna 연구 모델은 웹에 통합하지 않았으며 현재 저장 모델을 교체하지 않는다.

## 시연 방식과 준비도

**PPT 스크린샷 시연은 즉시 가능**, 실제 라이브 흐름은 이번 Chromium 검증에서 성공했다. 다만 시험 앱은 안전하게 정리했으므로 라이브 발표 전 새 격리 환경과 데이터로 리허설해야 한다. 수동 발표자가3~4분에 마치는지 실측한 것은 아니며 아래는 **3분40초 목표＋20초 여유**의 예상 시간표다.

모든 화면에 한 기능씩 오래 머무르기보다 ‘최종 식수로 계산→규격 발주→합격량 입고→재고 사용’의 일관된 숫자를 보여준다. 10개 화면을 모두 실시간으로 새로 작성하려 하지 않는다. 식재료·메뉴·규격은 사전에 준비하고, AI 예측은 사전 실행한 참고 결과를 이용해 대기 시간을 없앤다.

## 사전 준비 데이터

| 항목 | 준비 값 |
|---|---|
| 환경 | 원본/운영DB에 연결하지 않는 새 임시 SQLite 앱, 읽기 전용 소스/모델, 기존8000/8007포트 미사용 |
| 계정 | 가상 영양사 계정(업무/기준정보 확인용). 비밀번호는 발표 자료·캡처에 노출하지 않음 |
| 식단 | 예시 기준일2026-10-16 석식. 참치비빔밥＋두부구이. 이번 캡처와 같은 과거 가상 식단임을 명시 |
| 재료·기준 단위 | 참치·쌀·두부 모두kg. 안전재고0 |
| 레시피 | 참치비빔밥: 참치100g, 쌀100g; 두부구이: 두부100g/인 |
| 명시 포장규격 | 참치5kg/캔500원, 쌀20kg/포대1000원, 두부3kg/판300원. 가상 단가 |
| 업체 | 가상 가나유통(참치/쌀), 가상 다온식품(두부) |
| 시작 재고 | 쌀50kg 선입고·lot, 참치/두부0. 시연 시작 전 출고·검수 이력 없는 새 환경 |
| AI·최종 식수 | 기존 모델로 예측을 미리 생성. 이번 캡처는 AI133, 수동360, 최종351. 라이브 AI는 다시 계산하면 달라질 수 있으므로 화면의 실제 값 사용 |
| 기한·원장일자 | 유효한 가상 기한을 등록. 검수·출고 원장은 실제 시연일에 생기므로 수불 조회는 시연일을 포함하는 주로 설정 |

이번 실행의 준비 파일은 임시 백업 `/tmp/snp-finalprep-wisanw0k/demo/seed.py`에 있다. config.test_settings의 /tmp SQLite를 확인하는 보호 단언이 있고 가상 데이터만 만든다. **운영 환경에서 실행하지 않는다.** /tmp는 영구 산출물이 아니므로 행사 전 개발자가 확인한 별도 안전 환경에서 다시 준비한다. 기존 DB를 초기화하거나 기존 시연 이력을 삭제하는 방식은 사용하지 않는다.

리허설 전에 다음을 확인한다.

1. `git branch --show-current`가 sprint-final이고 현재 미커밋 조리지시서 코드·0005/0006 migration이 포함되어 있는지 확인한다. 브랜치 이름만으로 미커밋 기능이 커밋돼 있다고 생각하지 않는다.
2. 새 임시 앱에서 migration을 적용하고 가상 기준정보·재고·메뉴·식단을 준비한다. 운영 .env/DB/볼륨과 분리한다.
3. 기존 모델의 예측을 사전 실행하고 조·중·석식 결과가 표시되는지 확인한다. 정상 SBERT 가중치가 없는 경우 fallback임을 설명한다. 결과가 없더라도 수동 확정 업무는 가능하다.
4. 별도 브라우저 프로필 또는 시연 전용 탭을 사용한다. 최종 식수 화면, 발주예정서, 검수, 수불, 조리지시서 순서로 북마크를 준비한다. 아래 ID1은 이번 폐기용 데이터의 예이며 새 환경에서는 실제 ID를 사용한다.
5. PNG/PDF/Excel을 발표 PC에 내려받아 오프라인에서 열어 둔다. 비밀번호/실제 개인정보/외부 관리 브라우저가 투사되지 않도록 한다.

## 예상 오류·대체 방안

| 상황 | 올바른 대응 | 대체 화면 |
|---|---|---|
| AI 실행이 느리거나 가중치/외부 네트워크 실패 | 사전 생성한 실제 기존 모델 결과 사용. 없으면 수동 확정 시연으로 전환하고 AI 실행 성공이라고 말하지 않음 | 04a_ai_predictions·04_headcount |
| 최종 미확정이라 발주 오류 | 날짜/끼니를 맞추고 확정 체크·저장. 강제로 미확정값을 AI로 대체하지 않음 | 04→05 |
| 규격/업체가 없어 환산 제한 | 준비 데이터의 기준 단위·명시 내용량 확인. 5kg/통 등의 값을 품명에서 추정하지 않음 | 05·06 |
| 이미 검수·출고 완료 | 기존 데이터를 지우거나 중복 실행을 우회하지 않음. 완료 조회/스크린샷으로 전환. 다음 리허설은 새 폐기용 DB | 08·09 |
| 두부도 필요하지만 참치만 검수함 | 모든 재료의 유효 재고가 있어야 식사 차감 가능. 두부 검수를 마치거나 남은 과정은 사전 검증 화면으로 전환 | 08→09 |
| 식단/레시피를 발주 후 변경함 | 계획이 재검토로 바뀔 수 있음. 시연 중 변경은 최종 확정/발주 전에만 수행 | 06·07 |
| 수불 입고/출고가 안 보임 | 실제 로그 기록일이 시연일임을 확인해 그 주를 조회. 고정10월 식단일과 로그일 혼동 금지 | 09_weekly_ledger |
| Excel/프린터 프로그램 미설치 | 다운로드 성공과 미리 열린PDF 또는PNG를 사용. 실제 프린터 인쇄 완료라고 하지 않음 | demo_artifacts/cooking_instruction.pdf,10_cooking_print |
| UI 표가 길거나 브랜드 문구가 S&P로 남음 | 1920×1080 캡처를 쓰고 공식 발표명과 기존 UI명이 다름을 설명. 코드를 급히 수정하지 않음 | 각 PNG |

발표 전 우선 해결할 것은 **새 안전 환경 재구성·가상 기준정보 확인·사람 기준4분 리허설·오프라인 파일 준비**다. 개별 중량 자동 해석·실제 원본의 대상집단별 식수·분할 납품 등 미완성 범위는 이번 시연에 넣지 않는다. 실제 기존 운영 서비스에 연결하거나 모델을 교체할 필요가 없다.

## 이번 작업 산출물과 재사용 범위

새 브라우저 주 흐름 및 보충 캡처 성공. 기존117개×SQLite/MariaDB 회귀는 기존 로그를 재사용했고 이번에는 새로 실행하지 않았다. 이번 PDF/Excel/15개PNG는 신규다. 시연 스크립트는 개인 테스트용 /tmp에만 두고 애플리케이션 소스를 수정하지 않았다.

현재 테스트 앱은 정리됨: 라이브 서버가 남아 있다고 가정하지 않는다. 추가 개발 없이 바로 활용할 자료는07의 화면 표·PNG15장·실제 생성Excel/PDF·04~05의 발표 근거 문서와 위3분40초 대본이다.
