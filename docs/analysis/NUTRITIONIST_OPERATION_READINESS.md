# SNP 운영 준비 수준 — Phase 1 후

2026-11-06 KST. 작업 브랜치 `feature/ui-redesign-three-modes`. 이 문서는 소스에서 검증한 결과와 **아직 예전 코드가 실행 중인 실제 Preview**를 구분한다.

## 판정

**소스의 명확한 P0 결함 일부를 수정하고 격리 회귀/E2E로 검증했다. 통제된 정상 시연에 적합하며, 실제 현업 전 과정 상용 운영 준비는 아직 미완료다.** 승인·배포를 하지 않았으므로 공개 Preview가 이번 수정본으로 바뀌었다고 안내하면 안 된다.

| 영역 | 소스 상태 | 실제 서비스/운영 제한 |
|---|---|---|
| 관리자 계층 | 기존 업체 경로 보호·감사 추가, 회귀 통과 | 배포 전이므로 실제 Preview의 기존 우회 위험이 해소됐다고 단정 불가 |
| MAIN 아이디 | dry-run/원자 rename/rollback 명령·FK 보존 테스트 | 실제 PK1 verify-admin 유지. admin으로 아직 바꾸지 않음 |
| 초기 비밀 | 새 관리자/demo 분리·기존 비밀번호 보존 | 실제 기존 비밀번호 분리 여부/공유 이력은 소유자 확인 필요. 이번 회전 안 함 |
| 공개 가입 | 승인 opt-in 준비 | 실제 auto 유지. 불특정 공개 이용자의 내부 쓰기 위험 남음 |
| 식수 보고 | AI/수동/최종/실측·오차 결측 구분 | 실제 서비스에는 미배포. 실측 입력 책임·UI·감사 이력 미완성 |
| 식단/업로드 | 완료 보호·원자성·재검토·참조 삭제 보호 | 과거 발행본 snapshot/재발행 정책은 후속 |
| 발주/입고 | 기존 정상 경로 유지·전체 회귀 | 취소·재발주·반복 분납/정정/반품은 미완성 |
| 금액 | 기록 금액 서비스·미등록 세금 가산 제거·업체 ID 구분 | 세금/회계 확정·원가·예산 미구현. 검토용 합계만 제공 |
| UI | 3모드 유지, 빈 메뉴·요약 글자·모바일 개선 | 실제 사용자 수용·접근성 인증/전체 native zoom 검증 아님 |
| AI | 기존 모델/학습 산출물 보존·추론 회귀 | DB 현재 메뉴 연결/정확도·새 연구 모델 통합 미완료 |
| 운영 | 테스트 격리·기존 서비스 보존·임시 자원 정리 | 외부 SMTP·정기 off-host 복구·부하/장애·보안 전체성 검증 없음 |

## 별도 승인이 필요한 실제 작업

1. **관리자 username 변경**: 현재9계정/활성 MAIN1/PK1/대상 이름 충돌 없음이 사전 조건이다. 실행 직전 재검사·최신 백업의 격리 복원·seed 보호 확보 후, 기존 PK1만 verify-admin→admin으로 변경. 비밀번호/이메일/권한 보존. 명령/롤백은 구현 보고서 참고. 이번에 실제 변경하지 않았다.
2. **기존 비밀번호 변경**: username 변경과 다르다. 현재 암호를 모르거나 시범 계정과 같은 초기 비밀이 공유됐다면 소유권 확인 후 별도로 승인받아 처리한다. 고정 비밀번호 설정/추측 로그인 금지.
3. **공개 가입 정책 전환**: 실제 영양사 확인·승인 책임자/체험 정책 합의 후 opt-in. 기존 가입자 일괄 정지/권한 회수는 하지 않는다.
4. **Preview 배포**: 새 admin secret 파일 준비, Compose 검증·기존 SMTP/env 보존, 최신 백업·복구 확인, UI Preview web/proxy 등 필요한 서비스만 명시 대상으로 작업. 지금 이 배포는 수행하지 않았다. 운영 8000/8007/8010은 대상 아님.
5. **Phase 2 schema/정책**: 반복 분납/검수 정정·취소·발행본 보존의 승인 책임, 상태 전이·이관/롤백 검토 후 구현. 파괴적 migration 자동 실행 금지.

승인 요청의 출처는 이번 사용자 지시의 A-1 “실제 Preview 계정 변경은 사용자 승인을 받은 뒤 수행” 및 배포/정책/비밀번호 변경 금지 조건이다. 승인 없이 진행하지 않은 것이며 도구 접근 실패 때문이 아니다.

## 현업 사용자 수용 체크리스트 — 아직 수행자 인수 없음

모든 항목은 미인수다. 개발자 E2E 통과와 별도로 실제 영양사·업체가 수행하고 관찰자·일시·실패/재시도·작업 시간을 기록해야 한다. 비교 기준을 정하기 전 임의의 '업무시간 N% 절감' 수치를 만들지 않는다.

| 사용자 | 과제 | 관찰할 수용 기준 | 증거 기록 |
|---|---|---|---|
| 영양사 | 식단/레시피 작성→식수 확정 | 도움 없이 메뉴 찾기, 단위/필수 입력 이해, 네 식수 의미 구분 | 소요시간·도움 횟수·입력 누락/오해 |
| 영양사 | 소요량→명시 규격→업체별 발주 | 수량·올림·재고 근거 설명, 실제 주문 전 최종 확인 가능 | 검산표·화면/Excel 대조·오발주 여부 |
| 영양사 | 변경/오류 후 복구 | 재검토/충돌 메시지 이해, 중복 발주 없이 수정 | 실패 원인·복구 단계·반복 입력 부담 |
| 영양사/재고 | 실납/합격량→재고/수불 | 합격량만 입고, 중복 요청 식별, 기초/기말 대사 | 로그·lot·출력문서 일치 |
| 영양사 | 조리 문서·정산 검토 | 조리 지시와 사용 확정 구분, 미확정 세금/실측을 오인하지 않음 | 인쇄물/화면·담당자 확인 |
| 공급업체 | 가입→소속 확인→자기 주문 | 요구 정보·대기 사유 이해, 타 업체 데이터가 보이지 않음 | 도움·불필요 입력·계정 연결 확인 |
| 공급업체 | 접수/거절→납품 계획→출고 | 품목·규격/수량·단가·예정일 이해, 단계별 완료 인지 | 작업시간·오입력·중복 제출·상태 이해 |
| 공급업체 | 부분 납품/지연/반품·검수 결과 | 실제 업무 예외를 끝까지 복구 | 현재 반복 분납/반품은 미완성: 인수 보류 |
| 관리자 | 일반 계정/업체 승인·SUB 신청 | MAIN/SUB 범위 이해, 자기/상위 계정 우회 불가 | 승인 근거·감사 대사·권한 오류 이해 |
| 모든 역할 | Green/Civic·키보드/확대·모바일 | 글자/표 읽기, 저장 성공/실패/충돌 인지, 출력 일치 | 사용자 선호·작업 시간·접근성 문제 |

## 전시 게이트

배포 승인 전에는 기존 검증 자료와 제한된 격리 시연을 사용한다. 공개 체험을 허용하려면 관리자 비밀/가입 정책을 먼저 통제한다. AI 정확도·실측 입력·정산 지급 확정·반복 분납/반품·조리 완료 관리 등 미구현을 대본에서 제외한다. QA/XSS 시험명은 보안 회귀 증거일 뿐 전시용 실제 마스터가 아니므로 별도 합성 전시본이 필요하다. 기존 DB를 삭제/정리하라는 뜻은 아니다.

## 상용 도입 게이트

실제 시설을 선정하고 단일 시설 범위·영양/알레르기·단위/수율·실측 식수·취소/분납/반품·세금/마감 책임을 확정한다. Phase 2 후 예외/동시성/복구·사본 이관을 검증하고 사용자 인수, 실제 메일, 백업/복구·모니터링·보안/성능·접근성 검사를 완료해야 한다. 다기관 제공 시 조직 데이터 격리를 선행한다. 영양성분/알레르기 계산은 검증된 출처와 책임 체계 없이 안전 정보로 제공하지 않는다.

실제 관리자 안전 접근 방법과 최초 계정 조사 결과는 제품 감사, 최신 소스 변경/승인 절차는 구현 보고서, 실행 수치는 테스트 보고서가 기준이다.
