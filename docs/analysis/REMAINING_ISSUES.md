# 미완료·수동 확인 사항

기능 상태와 완료 기준은 REQUIREMENT_TRACEABILITY_MATRIX.md 및 requirement_catalog.json을 따른다. 이 문서의 사항을 성공으로 간주하지 않는다.

## P0 — 실제 데이터에 적용하기 전 확인

1. **기존 재고의 lot 대사** (INV-FIFO PARTIAL)
   - 신규 입고·증가 조정은 lot를 생성하고 사용·폐기는 FIFO로 배정한다. 만료 lot 출고와 유효 lot 부족을 차단한다.
   - 기존 재고에는 당시 lot/유통기한 배정 이력이 없을 수 있다. 그 이력을 추정해 만들거나 과거 로그를 재작성하지 않았다.
   - lot가 전혀 없는 기존 재고는 기존 수불 차감 기능을 보존하지만 FIFO 증거가 생기지는 않는다. 일부 lot만 있는 재고는 배정 잔량이 부족하면 차감이 차단될 수 있다.
   - 실제 전환 전에 재고 실사와 lot 기초 대사를 승인받아 수행해야 한다. 현재 작업은 기존 DB를 변경하지 않았으므로 실재고의 FIFO 완료를 주장하지 않는다.
2. **운영 스키마·계정 역할 확인**
   - 새 마이그레이션은 테스트 DB에만 적용했다. 운영의 migration 이력/중복 데이터/정확한 DB 버전은 별도 확인한다.
   - 기존 공급업체 User가 NUTRITIONIST 등으로 등록됐는지, 관리 계정의 staff/ADMIN 권한이 적절한지 점검한다. 이번 작업에서 운영 계정을 변경하지 않았다.
   - 공급업체/포장규격을 확인하지 않은 기존 품목은 발주가 제한된다. 기존 자유문자 spec을 숫자 계수로 추정하여 자동 채우지 않았다.

## P1 — 미완료 업무 및 외부 자료

- **조리지시서 시스템 통합: MISSING (TK-09-004).** 통합 기준 두 브랜치와 현재 코드에서 전용 조리지시서 구현을 발견하지 못했다. 별도 구현된 브랜치/커밋/파일을 확보해야 한다. 새 메뉴 조리 정보 입력, 주간 레시피 명세서, 발주예정서는 조리지시서를 대체하지 않는다.
- **정상 SBERT와 연구 성능 검증: UNVERIFIED/PARTIAL.** 오프라인의 실제 모델 로드/추론은 통과했지만 SBERT 가중치 캐시가 없어 텍스트 특성을 제외하는 기존 fallback을 사용했다. 모델 정확도, OOF/Holdout, 데이터 누수, 영양사 예측과의 정량 비교는 연구 산출물 없이는 완료 판정하지 않는다.
- **재검토 발주의 취소·대체 확정 UI.** 식단/식수/레시피/규격 변경 시 발주를 재검토로 표시하고 검수·입고를 차단한다. 새 발주예정서를 생성할 수 있지만 기존 발주의 취소/대체 관계를 완결하는 UI는 후속 작업이다. 기존 이력을 임의 삭제하지 않는다.
- **분할 납품·검수 정정.** 현재 한 OrderItem의 검수는 한 번 확정하며 같은 내용 재전송만 허용한다. 확정 후 수량 변경은 거부한다. 추가 분할 납품, 반품 후 재입고, 확정 검수의 정정 전표 정책은 별도 정의가 필요하다.
- **월말 정산.** 업체별 발주 금액, 실제 검수 합격 수량에 비례한 금액, 미검수 경고 및 월 수불 연결은 구현했다. 실제 소비를 업체별 원가로 배부하는 방식, 세금/운송비/청구서/차액 정산은 미정이다. 계산 결과를 회계 확정 자료로 간주하지 않는다.
- **월간 작성 화면.** 월간 조회/날짜 편집/주간 편집/일·주·월 파일 업로드는 유지했다. 기존 월간 신규 작성 화면은 업로드/일·주 작성으로 안내하는 구조이며 전용 월간 일괄 저장 폼은 완성되지 않았다.
- **독립 구입요구서 초안.** 기존 발주 자료를 이용한 생성과 카테고리 중복 제거는 구현했다. 독립 초안 편집·승인·빈 대상 확정 제한은 보강 대상이다.
- **실제 분류·납품규격 대사.** 관리 UI를 구현했지만 실제 카테고리 오분류, 공급 브랜드·700g(70g×10개) 등의 공급 자료 진위는 현업 확인이 필요하다.
- **칼로리·영양소.** TK-08-002에 등장하지만 원천 데이터/저장 모델이 없다. 임의 영양 수치를 만들지 않았다.

## P2 — 사용성 및 추가 검증

- 기존 모든 편집 화면을 단위/확정 상태 UX로 통일하는 작업, 업로드 오류 다운로드 형식 통일.
- 수량은 저장 정밀도 때문에 일부 표에 소수 6자리까지 표시된다. 현업 표시 자릿수/올림 기준을 확인할 것.
- 정상·오류 입력의 자동화 검증과 핵심 브라우저 흐름은 수행했지만 모든 레거시 GET 파라미터 조합, 모든 화면의 모바일/키보드 동작을 검증하지는 않았다.
- 대량 문서의 페이지 나눔, 실제 프린터 오류/재시도, 현업 가독성 인수는 미완료다. 단일 사례의 PDF 생성과 화면 캡처만 검증했다.
- 동시 요청 부하·장애 복구·대량 업로드 성능 테스트는 미실시다. 트랜잭션·행 잠금·고유키 및 순차 중복 요청 테스트를 동시 부하 테스트로 대신 판정하지 않는다.

## 실제 배포 전 조치

1. 운영 데이터 백업 및 별도 복제 DB에서 migration/기초 lot/공급업체·규격 대사 검증.
2. 기존 계정 권한·업무 접근 정책 확인 및 신규 기준정보 입력 담당자 지정.
3. kg/g/EA 등 기준 단위, 포장 1단위 내용량, 포장 단가, 발주 간격 확인. 캔/봉=1, 소수 kg=0.01 등은 반드시 등록된 값을 사용한다.
4. 재검토/취소·검수 정정·분할 납품·반품·회계 정책 결정.
5. 정상 SBERT 가중치 준비와 실제 입력의 모델 검증, 서비스 품질 기준 승인.
6. 영양사의 실제 양식·출력·업무 인수 테스트.
7. 검증 결과를 승인받은 후 별도로 배포한다. 이번 작업에서 push/PR/서비스 배포를 수행하지 않았다.
