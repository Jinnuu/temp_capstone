## 1. 전달할 메시지와 범위

발표 핵심 문장: **“AI는 식수를 제안하고 영양사가 최종 결정합니다. 확정 식수와 실제 납품규격으로 발주를 만들고, 업체 응답과 구매자 검수를 거쳐 합격량만 재고에 반영합니다.”**

- 포함: 식단·레시피 확인, 기존 모델 예측 참고, 수동/최종 식수 구분, 재료량·포장 환산, 업체별 발주, 업체 수락/출고, 검수 입고, 수불, 조리지시서 Excel, 관리자 신청/소속 승인 화면.
- 제외: 새 연구 모델/Optuna 적용, 실제 AI 정확도·시간 절감률 주장, 영양소/알레르기 안전 보장, 취소/재발주·반품·반복 분납, 회계 확정/지급 완료, 조리 완료 상태 기록, 모든 관리자 경로 보안 보장.
- 역할: 영양사·공급업체·MAIN_ADMIN 세 개 브라우저 프로필. 역할을 바꾸기 위해 실계정 권한을 수정하지 않는다. 재고/조리 담당자의 기존 역할 분리는 설명하되 시간상 영양사의 허용된 화면으로 핵심 흐름을 보여줄 수 있다.
- 디자인: Green을 기본으로, Civic을 동일 화면에서 한 번 전환한다. Reference 보존은 설명만 한다. 1920×1080 기준, 모바일은 미리 준비한 기존 화면으로 보조한다.

## 2. 사전 준비: 실행 전 승인된 격리 환경에서만

아래 데이터는 **준비 명세**이며 이번에 생성하지 않았다. 자료를 준비할 운영자가 서비스/DB 이름과 격리를 먼저 확인해야 한다. 기존 Preview DB를 초기화하거나 전시용으로 청소하지 않는다.

| 항목 | 준비할 합성 데이터·조건 |
|---|---|
| 계정 | 각각 다른 비밀을 가진 시연용 영양사/업체 A/MAIN. 기존 실제 verify-admin의 비밀번호를 PPT/스크립트에 넣지 않음. 별도 업체 B는 IDOR 보조 설명용 |
| 업체 | 실명이 아닌 '시연 식재료 A/B'. 업체 A와 계정의 검증된 membership. 관리자 장면용 별도의 합성 공급업체 가입/관리자 신청 대기 레코드 |
| 식단 날짜 | 시연일 또는 다음 납품 가능일 D. 날짜·끼니가 실제 계획/예측·납품 필터와 일치해야 함. 과거 고정 날짜를 무조건 사용하지 않음 |
| 메뉴/레시피 | '시연 채소볶음', 재료 '시연 채소' 1인량100g. kg 재고 단위, 명시적 5kg/봉 규격. 다른 메뉴가 없는 단순 계산으로 시작 |
| 재고/안전재고 | 최초0kg/안전재고0kg. 유통기한은 시연일 뒤로, 다른 주문·로트와 섞이지 않음 |
| 식수 | 수동 예상110명, 영양사 최종100명. AI 예측은 기존 모델이 실제 반환한 값을 별도로 보여주며 특정 숫자로 조작하지 않음 |
| 단가 | 명시 규격1봉 가격500원인 합성 표본. 발주2봉=견적1000원. 세금은 미확정이므로 지급액으로 설명하지 않음 |
| 납품/검수 | 업체 예정10kg → 실제10kg → 합격10kg. 전량 입고 정상 경로로 제한 |
| 문서 | 식수/규격/레시피 누락 없음. 조리지시서 메모는 '가열 전 세척' 등 합성 지시, 개인정보 없음 |
| 환경 | 시연 전 URL·DNS·TLS·정적파일·로그인/로그아웃 확인. 실제 SMTP 미설정이면 메일 수신 시연 제외 |
| 백업 대안 | 준비된 PNG·Excel·인쇄 PDF의 오프라인 사본. 실시간 서비스 실패 시 DB를 복구/초기화하려 하지 않음 |

계산 검산표:

- 100명 × 100g = 10,000g = **10kg**.
- 10kg ÷ 명시 규격5kg/봉 = **2봉**. 자유문구에서 중량을 추정한 결과가 아니다.
- 발주/공급업체 수락/출고 단계 재고 **0kg 유지**.
- 검수 합격10kg 확정 후 재고 **10kg**.
- 별도 명시적 사용 확정10kg 후 **0kg**. 주간 수불은 기초0+입고10−사용10−폐기0+조정0=기말0.
- 조리지시서는 최종 식수 기준 **10kg**을 표시한다. 메모/Excel 다운로드로 재고 로그가 추가되지 않는다.

선행 확인: 실제 발주 입력/업체 포털에서 표시하는 '필요 기본량kg'과 '발주 포장 수2봉'을 구분해서 읽는다. 계획 ID·주문 ID·품목 ID·조리 식단 ID는 생성 결과에서 클릭하며 예시 숫자를 URL에 고정하지 않는다.

## 4. 관리자·권한 장면의 정확한 설명

- MAIN_ADMIN: 관리자 신청 승인/거절과 SUB 임명, 전체 감사·계정 관리.
- SUB_ADMIN: 일반 계정·업체 소속·허용 업무 운영. 새 관리자 화면에서 MAIN/다른 SUB/본인 관리자 권한 변경은 금지된다.
- 공급업체 SUB 겸임은 MAIN 승인 시 허용되지만 포털은 소속 업체로 제한되고 검수 합격량/재고 쓰기는 제외된다.
- 일반 공급업체가 영양사 메뉴/API에 접근하지 못하는 증거는 기존 격리 테스트로 설명한다. 실제 공개 서비스에 타 업체 ID를 넣어 시험하지 않는다.
- **현재 발견한 기존 업체 편집 경로의 대상 보호 누락(AUD-01)은 해결 전이다.** 따라서 “모든 경로의 관리자 계층 권한이 완전하다”는 대본은 사용하지 않는다. 필요하면 관리자 장면을 신청/감사 조회만으로 제한한다.

- TLS/DNS/서비스 오류: 재시작·운영 설정 변경 대신 오프라인 PNG·Excel·PDF로 전환하고 '기존 검증 결과'라고 알린다.
- 비밀번호 모름: 추측/재설정/공유 비밀번호 사용을 무대에서 시도하지 않는다. 소유자 확인 후 별도 승인된 접근 준비가 안 됐다면 해당 역할은 화면 자료로 대체한다.
- AI 추론 실패: 수동110→최종100으로 업무를 계속하고 예측 실패를 숨기지 않는다. 임의 예측값/정확도 숫자를 넣지 않는다.
- 미확정 식수/레시피·규격 누락: 경고를 보여주고 사전 준비된 정상 합성 레코드로 이동. 자유문구 중량을 추정하거나 DB를 급히 편집하지 않는다.
- 409 충돌: 새로고침 후 실제 최신 상태를 확인하고 입력을 다시 검토한다. 상태 전이를 건너뛰거나 강제 API 호출하지 않는다.
- 재검토/거절/이미 검수된 주문: 취소/반복 납품이 완성된 것처럼 시연하지 않고 준비된 미처리 주문으로 전환한다.
- Excel/인쇄 문제: 이미 검증한 파일을 열고 사전 출력 자료임을 설명한다. PDF를 실제 현장 프린터 출력 성공의 증거로 쓰지 않는다.

## 6. 리허설 수용 체크리스트

아래는 **아직 이번 작업에서 실행하지 않은** 후속 리허설 기준이다.

- [ ] 해당 앱과 DB가 운영/현재 Preview 데이터와 격리됐는지 확인.
- [ ] 세 역할의 독립 인증·로그아웃과 비밀번호 비노출, MAIN 초기 비밀 분리 확인.
- [ ] Green/Civic 전환·이동 후 모드 유지, 입력/저장/재조회 정상.
- [ ] AI/수동110/최종100의 의미와 현재 모델 입력 한계를 설명 가능.
- [ ] 100명×100g=10kg, 5kg/봉=2봉, 업체·예정일·단가 스냅샷 일치.
- [ ] 수락/출고 전후 재고0, 검수 합격 후10, 명시적 사용 후0.
- [ ] 동일 요청 중복 반영 없음. 재검증은 격리 DB에서만 수행.
- [ ] 수불 합계와 실제 로그/lot 잔량 대사. 조리 메모/Excel 후 재고 추가 변경 없음.
- [ ] 업체 소속 승인·관리자 신청/SUB 승인·감사 재조회 증거 확보.
- [ ] 회계 확정·실측 정확도·미구현 조리 상태/분납 기능을 과장하지 않음.
- [ ] 오프라인 파일과 화면 데이터를 익명화하고 QA 시험명 없는 전시본 준비.
- [ ] 실행일/브랜치/환경/관측값/미실행 단계를 적어 기존 증거와 구분.

## 7. 현재 시연 가능 여부

기존 실행 증거상 통합 정상 경로는 시연 후보로 적합하다. 그러나 이번 읽기 전용 감사는 현재 계정의 비밀번호 성공·위 준비 데이터·신규 7분 리허설을 확인하지 않았다. **조건부 시연 가능**으로 판정하며 공개 체험/관리자 보안 보장/실측 AI 평가/정산 확정을 약속할 수준은 아니다. 먼저 전시 게이트를 결정하고 승인된 격리 리허설을 완료해야 한다.

## 후속 소스 개선 반영과 리허설 상태

Phase 1 소스로 기존 영양사21지점·공급업체/관리자12지점·신규P0 8지점의 격리 브라우저 검증을 새로 통과했다. Green/Civic36개 화면과 개선 화면을 `verification/nutritionist-hardening-20261106/`에 확보했다. 이 결과가 위 7분 대본을 실제 현업 사용자가 인수했다는 뜻은 아니다.

새 소스에서는 기존 업체 관리자 보호, 실제 식수 보고 의미, 완료 업로드 보호, 임의10%/동명 업체 집계가 개선됐다. **현재 공개 Preview에는 아직 적용하지 않았다.** 위 시연 준비 시 배포 버전을 반드시 확인한다. 실제 관리자 아이디는 verify-admin이며 admin으로 안내하지 않는다. 비밀번호/실제 가입 정책/배포 변경은 별도 승인이다.

발주 취소·반복 분납·검수 정정·불변 발행본/실측 입력은 여전히 시연 완료 기능에 포함하지 않는다. QA/XSS 시험 데이터는 새 회귀 화면에도 존재하므로 전시용 마스터로 사용하지 않는다. 새로운 준비 데이터/실제7분 리허설·현업 인수는 후속이다.
